# The wolf token inventory facsimile's highlighter is generated from

`load_wolf_syntax` in `src/syntax/syntax_highlighter_module.f90` is the output
of this document, not of anyone's memory of the language — which is what lets
ls05's grammar-drift check cover a table that lives in another repo.

**Source of truth**, at pin `70bdd35`:

- `vendor/upstream/spec/grammar.ebnf` — `reserved_kw`, for the keyword set.
- `upstream/spec/01-grammar.md` §1.2, §1.5, §3.2, §6 — comments, string forms,
  and the operator climb.

This is the same inventory `clients/fackr/inventory.md` records, in a different
target language. That is deliberate: two independently-written tables generated
from one pinned grammar are a cross-check on the extraction, and a drift in
either is a drift in both.

**The extraction gap ls02 recorded still stands at this pin.**
`grammar.ebnf` is generated by `wolf xtask spec-extract`, and the extraction
elides the precedence climb — the file says so itself. The quoted terminals it
carries are missing `==` `!=` `<` `>` `<=` `>=` `<=>` `&&` `||` `<<` `>>` `/`
`&`; only `spec/01-grammar.md` §3.2 has them. A drift check reading
`grammar.ebnf` alone therefore cannot see an operator change. Two ways out,
both upstream: teach `spec-extract` to emit the climb, or have the drift check
read §3.2's table directly.

## Keywords — the closed set of 50 `[gram.inv.kw]`

Verbatim from `reserved_kw`, and the count is the spec's own checksum:

```
as asm assume borrow break comptime const continue copy defer distinct dyn
else enum errdefer export extern false fn for freeze handle if impl import in
let loop match move mut proc pub region return scope select shared spawn
struct take trait true type unsafe use var weak when while
```

**Contextual keywords are excluded** (`[gram.inv.ctx]`): `c`, `rc`, `pool`,
`from`, `timeout`, `noalias`, `pkg`, `reg`, `self`, and the asm operand
directions. Each is an ordinary identifier everywhere except one position, and
facsimile's tokenizer cannot see position. Painting `from` and `timeout` as
keywords would be wrong far more often than right.

In Fortran these land as a `character(len=8)` array of 50 elements — 8 because
`comptime`, `continue`, `distinct` and `errdefer` are the longest at eight
characters. Every literal in one array constructor must be the same length, so
they are space-padded to 8 and `compare_word` trims.

## Types

```
bool int str Self
```

Small, and deliberately so. Wolf has **no fixed-width scalar inventory at this
pin**: `i32`/`u64`/`f64` and friends appear in neither `grammar.ebnf` nor any
`spec/*.md`. Every name above is one the pinned spec or corpus actually
contains. Guessing the rest would be inventing language surface in an editor
table, which is how a highlighter ends up teaching people a language that does
not exist.

`type` and `region` are also type-level (`type ::= … | 'type' | 'region'`) but
they are reserved keywords, so they are already in the set above.

## Operators

```
<=>  <<=  >>=  ..=
==  !=  <=  >=  &&  ||  <<  >>  ..  ->  =>  +=  -=  *=  /=  %=  &=  |=  ^=
+  -  *  /  %  &  |  ^  !  <  >  =  ?  @
```

**Ordering does not matter here, unlike in fackr.** facsimile's
`is_operator_char` asks only whether a character appears anywhere in any entry
(`index(trim(op), ch) > 0`), so the array is used as a *character set* and
every operator becomes a one-character `TOKEN_OPERATOR`. The multi-character
entries are carried anyway so the table reads as the language's operator list
and so a future longest-match tokenizer inherits the right data.

The effective character set is therefore: `< = > . & | ! + - * / % ^ ? @`.
Note that `.` enters through `..` and `..=`, so field access and tuple indexing
colour their dot as an operator. That is cosmetic and arguably right.

`^` carries two jobs (bitwise xor, and D25's from-end index marker `s[^1]`) and
`!` three (prefix not, the `!T` error-union type, and `!=`) — a tokenizer that
only colours them does not have to tell them apart.

## Comments and strings

| field | value | why |
|-------|-------|-----|
| `comment_single` | `'//'` | `[gram.lex.comment]`; covers `///` and `//!` |
| `comment_start` / `comment_end` | *(empty)* | **wolf has no block comments** — "nesting arguments lose to simplicity + lexer speed". `check_multiline_comment_start` guards on non-empty, so leaving these unset is the correct encoding of "there is no such form" |
| `string_delimiters` | `['""" ', '"   ']` | `[gram.lex.str]`; there is no character literal |
| `case_sensitive` | `.true.` | |
| `has_preprocessor` | `.false.` | |

**The `"""` entry must come first**, and this is a real constraint rather than
a style preference. `process_string` takes the *first* delimiter that matches
at the cursor, and only turns on multiline mode when the matched delimiter is
three characters or longer (`is_multiline = (len(delimiter) >= 3)`). Listing
`'"'` first would match the first quote of a `"""` fence and make wolf's block
string form unreachable.

This is not hypothetical: facsimile's **Python** table lists `"` before `"""`
and has exactly that bug today. It is filed in `patches/STATUS.md` rather than
fixed here, because it is a Python problem that this sprint merely noticed.

## What the table cannot express

facsimile's tokenizer is a byte-indexed single pass, so three real parts of
wolf lexical structure are out of reach. None is a reason to add a shim — they
are the argument for semantic tokens whenever the compiler ships them
(post-v1):

1. **F-string interpolation.** Every string literal is an f-string, and `{x}`
   re-enters token mode inside it (`[gram.lex.str]`). The whole literal colours
   as a string, so the expression inside an interpolation is not highlighted,
   and `{{`/`}}` escapes are invisible.
2. **Generalized literals.** `re"[a-z]+"` and `path"/etc/hosts"` are an
   identifier fused to a string; the prefix colours as an identifier, which is
   not wrong, just not special.
3. **Raw strings.** `r#"…"#` fences balance by count. The `r` colours as an
   identifier and the body as a string only by luck of the delimiters.

Attributes (`#[…]`) colour as `#` plus punctuation: `has_preprocessor` is
`.false.` for wolf, so the `#` does not become a preprocessor token. Setting it
`.true.` would be worse — it would swallow the rest of the line.
