### What the std-loading server changes

**For this harness: nothing has to change for it to stay green, and nothing
in it tests the change.** The harness spawns `<bin> lsp` with the caller's
environment and no flags. On kasumi and in CI the binary is the unpacked
archive's, so `std/` is beside it and the server loads it; a developer whose
`WOLF_BIN` is a plain `cargo build` of wolf-lang has none beside it and gets
the std-less server, and the 71 sessions answer the same either way, because
no sample reaches a std module. Three consequences:

1. A stray `WOLF_STD` in the environment now reaches the server. It cannot
   move a transcript today (same reason), but one naming a non-directory
   makes every session fail at spawn with exit 2.
2. `onetruth` (publishDiagnostics == `conform-run`) holds only while both
   sides see the same std. They do: both are the same binary in the same
   environment.
3. A session that does reach std is owed, and the recorder cannot write one
   yet: `definition` on a std method answers the std file's absolute
   `file://` path, and `capture`/`record` elide only `$WS` and `$REPO`. The
   samples rule (`vendor/README.md`: corpus files only) also has no file
   that calls a home-module method. Listed as an issue to file, not built.

**For an editor's default configuration: nothing, when `wolf` is an
installed toolchain.** Plain `wolf lsp` is still the right command line for
every client here and for yew's row (`cmd: "wolf", args: ["lsp"], roots:
["wolf.pkg", ".git"]`): the server finds the `std/` installed beside the
real binary, through a `PATH` symlink too (measured on linux; Homebrew's
layout on macOS was not run by this lane), and reads a `std` path dependency
from the opened file's own `wolf.pkg`, not from the client's root. The roots
only choose `rootUri`. `--std-root <dir>` is for a `wolf` with no std beside
it (a source build) or for reading a different std, and a client that adds
it must name a real directory: a wrong one is an exit 2 before `initialize`,
which an editor shows as a server that will not start. `--stdio` and
`--std-root` combine.

**`helix-health` SKIPS on kasumi** (`lsp3/helix-health.log`: `no hx (or
helix) on PATH`, rc 77) as at every tl lane; CI's helix job is the run that
counts.
