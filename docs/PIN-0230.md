### What #42 changes

- **For the harness.** A session's std is its script's business: the caller's
  `WOLF_STD` is removed from every `wolf` the harness spawns (the LSP session
  and onetruth's `conform-run`), and a script that wants a root spells `env
  WOLF_STD …`, applied after the removal. `std none` (a header directive, like
  `env`) runs a lone hard link or copy of the binary in a scratch directory,
  removed when the session drops; it is the only way to reach the no-std
  server, because the default root is found from `current_exe` with symlinks
  resolved, and a root naming an empty directory answers E0403, not E0301
  (`probe/g-empty-planted.txt` shows the difference on this very sample).
- **For the recorder.** `$STD` joins `$WS`, `$REPO` and `$TMP`, elided after
  `$WS` and before `$REPO`, from the root the spawned server will load: a
  script's `WOLF_STD`, else the `std/` beside the canonical binary. Captured
  editor transcripts (`lspconf capture`) do not elide it yet: no captured
  smoke reaches std, and the proxy does not know which `wolf` the editor
  would have run. A developer whose `WOLF_BIN` is a plain `cargo build` of
  wolf-lang has no `std/` beside it, and `std/reach` then mismatches (E0301):
  the transcript records the installed toolchain, as `doctor` does.
- **The sample.** The corpus pins `typecheck/method_home_no_std.lu` as
  `fail(E0301)` because wolf-lang's corpus runs a checkout build with no std
  beside it; a released server reads the same bytes cleanly. The two
  transcripts are that file read both ways.
