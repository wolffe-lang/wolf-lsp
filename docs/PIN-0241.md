# The pin at 0.2.41

The move from wolf 0.2.36 (`5adf3d9`) to wolf 0.2.41 (`0261597`), five releases in one step.
Measured on the macOS development machine (darwin arm64) against the acquired release archive; CI's
server lane replays the same library on linux, macOS and windows.

## 1. Forbidden

- No change to the server, the harness's matching or the normalizer to make a transcript pass; no
  transcript edited by hand. Scripted transcripts come from `lspconf rerecord`, captured smokes from
  replay (restamped only when every record matched) or from the real editor.
- No client gains a list of prelude functions.
- The pin is the release by digest, never wolf-lang's trunk (`56a8dad2`). No compiler source read:
  the server crates are compared by tree id only.

## 4. What moved, and why

- **`errors.lu`'s open publish**: `[]` at 0.2.36; at 0.2.41, two E0301 ("nothing defines
  `acquire`", line 26; "nothing defines `release`", line 27) and one E0808 ("`io.Error` carries 0
  values, but this pattern binds 1", line 38). 0.2.41 makes a provisional prelude stand-in that
  nothing defines E0301 (wolf-lang#1083), and its release note names `errors.lu` as the one corpus
  file that moves ("unsupported before, E0301 at typecheck now"). E0808 is an older rule that the
  file now reaches, because it is no longer declined before typecheck. onetruth agrees: the server
  and `conform-run` give the same three. Two scripted transcripts and the emacs smoke open
  `errors.lu`, and each moved in exactly that record.
- **The emacs smoke, re-captured** by `clients/emacs/README.md`'s recipe with GNU Emacs 31.1 and
  eglot 1.24.31, the versions of its previous capture. The ERT suite passed 1/1 while recording;
  against the committed file only the header and record 20 moved. Of three runs the second and
  third are byte-identical; the first ordered two independent notifications
  (`workspace/didChangeConfiguration`, `hello.lu`'s first publish) the other way round.
- **Nothing else**: no `c2s` line moved anywhere, and no other answer.
